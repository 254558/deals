## 二、抓取：两个域名、一枚匿名令牌

### 2.1 两个域名各管一半

迪卡侬中国官网自己用的 BFF 接口，公开 JSON GET，无需登录。前端把请求拆在两个域名上：

```
api-cn.decathlon.com.cn     发匿名令牌（identification）
  POST /facade_identification/connection/api/v1/dcn_cn/anonymous_token
  headers: x-api-key: <前端包里写死的那把>
  body:    { client_name: "DCN", social_id: <任意 uuid> }
  → { data: { user_token } }

mpm-store.decathlon.com.cn  商品数据（wcc_bff）
  GET /wcc_bff/api/v1/easymerch/plp/product_lists
      ?category_id=644a1c540c5c730001d1e6c1   ← 特惠专区
      &current_page=N&page_size=100&sort=DISCOUNTS&filter={}
  headers: Authorization: Bearer <token>, client-name: DCN
```

### 2.2 令牌是匿名的，自己取一枚就够

商品接口要 `Authorization: Bearer <token>`，而这个 token 是**匿名**的，由前端自己现取现用（`window.__NUXT__.state.token`，TTL 两小时）。所以这一站也自己取一枚，而不是去借浏览器的。两条实测结论决定了写法：

1. **`x-api-key` 是必需品。** 少了它令牌接口回 401 Unauthorized；而商品接口单独给 apiKey 也不行（它明确报 `Required request header 'Authorization'`）。两样都要。
2. **令牌里带 `exp`。** 代码把 JWT 的 payload 解出来（`base64url` 解 `split('.')[1]`），按真实过期时间缓存，**过期前 5 分钟**就换新的，免得翻页翻到一半失效；真被打回 401 时不是网络抖动，不重试，直接换一枚再打一次。

`social_id` 只是标识一个匿名访客，给任意 uuid 即可（`crypto.randomUUID()`）。

### 2.3 站点前面的 WAF 拦不到这里，所以不用起浏览器

`www.decathlon.com.cn` 挂了 FEC 的 JS 挑战，`curl` 直接 406。但上面两个域名**不在那层后面**，Node 直接 `fetch` 就是 200——所以这个工具完全不用起浏览器（不需要 Playwright / Puppeteer / 无头 Chrome）。这是这一站和优衣库最大的实现差别：那边是 WAF 按 UA 拦，这边是主站有挑战、接口域名没有。

请求侧的其他防护：单次 `AbortSignal.timeout(30_000)`；失败重试 3 次，退避 `800ms × (i+1)`；翻页之间 `sleep(200)`。

### 2.4 抓什么：特惠专区，不是按折扣率筛全站

商品池用的是站点自己的折扣区，分类 id `644a1c540c5c730001d1e6c1`（`DISCOUNT_ZONE`）。

**为什么不用 `filter={"discount_range":[...]}` 筛全站**：全站按折扣率筛出来的量（约 1572）和特惠专区（1391）基本重合，但那条路实测后端会**串页**——翻到后面会重复返回前面的商品。一个分类翻 14 页就完事，稳定得多。另一条硬约束：**`page_size` 上限是 100**（200 实测返回空）。14 页、去重后 1391 件，两次抓取零差异。

（1391 / 1572 都是合并前的实测值。合并后用同一套逻辑重抓，第一次拿到 1426 件——商品池本来就随档期浮动，数量对不上是正常的，不该对齐某个固定数。）

翻页按 `total_page` 翻到底为止，中间某页空了也停。`sort=DISCOUNTS`。

`findByCode`（`track` 用）还有一条兜底：先在折扣区里找，找不到就去「所有运动」根分类（`ALL_SPORTS = 644a1c540c5c730001d1dda2`）里搜一遍——因为要盯的常常是**还没降价**的商品，它当然不在折扣区里。

### 2.5 价格字段怎么读：`discount_rate` 是「折」不是降幅

| 接口字段 | 语义 |
| --- | --- |
| `list_price` | 官方原价（迪卡侬自己的划线价） |
| `active_price` | 现价 |
| `discount_rate` | **「折」，不是降幅**：`2.5` 表示 **2.5 折**，也就是降了 75%。换算关系是 `(10 - discount_rate) / 10` |
| `display_discount_rate` | 官网页面上显不显示这个角标 |
| `on_sale` | 这件还在不在售 |

**这个字段是这一站最容易踩的坑**：直接把它当「降幅」用会得到完全颠倒的排序。所以现在实现里，降幅**一律由两个价格现算**（`discountRate = 1 - active/list`），`discount_rate` 只在适配器的顶部注释里留档、说明它的口径是「折」，不再参与任何运算。口径落在共享核心的 `discountRate()`（[src/core/db.mjs](../src/core/db.mjs)）里，终端、数据库、报告三处调的是同一个函数，不会各算各的。

### 2.6 一个商品有多个 model

一件商品（`dsm_code`）下挂若干 model，各是不同颜色/款式、各有各的价格。榜上按「这件商品最划算的那一档」呈现：**先比降幅，降幅相同再比谁现价低**——捡漏榜要的是最划算的那档。

同一个 model 内各 SKU 的价格可能不同（接口用 `uniform_price` 标这件事，`false` 就是不统一）。`priceOf` 不看这个布尔位，直接在所有 `items[]` 里取最低的那个 `active_price`——榜上要的是最便宜的那档。`active_price` 或 `list_price` 非正的 model 直接跳过（脏数据）。

标签怎么来的：

- `sticker_info.contents` 里的角标文案 → 标签码：`尾货` / `清仓` → `endlife`，`新品` → `new_arrival`。**这是按页面文案反查的**，比读布尔位更贴近用户看到的东西。
- `is_endlife` 也补一个 `endlife`。
- `func_label_list` 里 `code === 'discount-zone'` → `discount_zone`（「特惠专区」）。这个标签**不当标签显示**，理由见 3.2。

去重按 `dsm_code`，翻页重叠时保留降得更狠的那条、把标签并起来。

## 三、报告：这一页为什么长这样

### 3.1 报头一行，报头下面直接是筛选

报头只有一行站点信息：站点名（`meta.label` = `迪卡侬`——连这个站名也归数据，不在组件里拼）、抓取时间，行尾是指向优衣库报告的入口。

> 2026-09-30 应要求去掉两处：站点名后面的「· 中国官网」（页脚已经写着数据源是 `decathlon.com.cn 公开接口`，报头不必再重复一遍），以及**「共记录 N 件」**（`showRecorded` 关掉）。
>
> `recorded` 仍留在 payload 里。它是数据库里的累计记录数，跟榜上实际有多少件本来就对不上、也是对的：前者说库里攒了多少（当时 1,434 件，含没图的、已不在特价的、谢绝名单里的），后者说这一期筛出来多少（1,278 件）。（工具栏右端那句「显示全部 N 件」2026-09-30 已撤。）

**报头紧接着就是筛选页签和商品列表**——打开页面第一眼就是榜单本身。原来那排总账数字（在售降价 N 件 / 全部买下可省 ¥X / 降幅 ≥50% N 件）删掉了，理由和优衣库那份一样：它们的问题不是不准确，是对「这一件要不要买」没有任何帮助。

**页顶榜单（RankBoard）这一站是关的**（`features.rankBoard: false`），首屏第一个元素就是筛选页签。这是**选择，不是少了什么**：迪卡侬的商品名下面是「品牌 + 编号」，榜单里再念一遍品牌很啰嗦，而优衣库的商品名本身就够短，摆得下一张榜。

### 3.2 刻意不挂、刻意改写的那几处

- **「特惠专区」不当标签。** 抓来的样本里 1391 件有 1374 件带着它——一个全都命中的标签等于没有标签，所以它连中文译本都不进 `tagLabels`（`tagLabel()` 拿不到译名就返回 null，调用方直接滤掉）。终端表格的标签列同样显式滤掉它。
- **不写官网的「6.0折」，改写降幅。** 官网把折扣写成「6.0 折」，这里写成 `-40%`：和榜单、标尺的口径一致，同一个数在三个地方是同一个说法。
- **折的角标和降幅的角标不是一回事。** 官网那张黄底角标是「折」，这一页的黄底角标（`.offbadge`）是降幅；两者颜色一样（`#FFCD4E`），因为官网就是用它表示折扣的。
- **图上角标换成我们自己的两个信号。** 官网 `.tag-box` 写的是「特惠产品」（人人都有），这里改写成红＝尾货清仓、灰＝新品——只有值得单独说的才挂。
- **卡片底部那条 chips 行没有标签也照样留着**：它的 `margin-top: auto` + `min-height` 托住卡片底边，整排卡片的底对齐才不会被「有没有标签、有没有收藏」带歪。
- **品牌提到名称上方单独一格。** 官网是把品牌内联在名称前面的，卡片上把它提上来单独站一行：迪卡侬的名称（「箭侧垫」）脱离品牌就读不懂是哪家的什么货；优衣库的名称（「抽褶裙」）不需要品牌来补，所以那一份不画这一行，编号在搜索里认。

### 3.3 列表视图已撤（2026-09-30）

原先还有一张「横着扫的表」：左边小图（1:1），中间商品名与品牌/编号，右边价格从上市价坍缩到现价，再往右一根墨色**降价标尺**（横轴是价格轴，左端上市价、右端 `￥0`），降幅黄角标和「省 ￥X」摆在条上方。应要求撤掉了——大图够用。

标尺本身没消失：卡片底部那根比例条就是它（`.card__bar`），长度同样等于降幅。**颜色仍然是迪卡侬那根条的墨色**：这一站黄＝折扣数、红＝清仓角标、蓝＝可点，条不属于这三类、它是一段数据，所以用官网的墨色；优衣库那份是红条（红＝降价，和它卡片上的红色现价一套）。

一并撤掉的还有四个只服务列表的开关（`rowMetaLine` / `rowChips` / `flatWasDash` / `scaleLayout`）、payload 里的 `meta.columns`（先换成 `meta.sorts`，排序入口撤掉后那份声明也删了）和整套表格 CSS（含表头粘性用的 `--headtop`）。

### 3.4 大图卡片

方图、名称（品牌内联在前）、现价＋`-90%` 黄角标＋划线的上市价、价格行右端两个动作。1440 宽下 4 列。

卡片骨架两家共用（图 → 名称 → 价格行 → 标尺/状态行 → chips），差异全部走 `meta.features`，组件里没有一处站点判断：

| 开关 | 这一站的值 | 理由 |
| --- | --- | --- |
| `stickerTags` | 开 | 商品图上的角标：红＝尾货清仓、灰＝新品。贴图左上角，位置照官网 `.tag-box absolute left-10` |
| `brandMark` | 开 | 名称前那块品牌小字。官网卡片就是 `p` + 内联品牌 |
| `priceOffBadge` | 开 | 价格行里的黄底 `-xx%` 角标 |
| `dealBarNumber` | 关 | 比例条只画长度、不写数字；数字在黄角标里，同一件事不说两遍（优衣库相反：数字在条尾、价格行只有价格） |
| `cardChips` | 开 | 卡片底部 chips 行，托住底边 |
| `trackChip` | 开 | `★ 待拔草`。优衣库不挂——实心蓝爱心已经在说这件事 |

一处和官网不同、两家都适用：官网卡片**不显示原价**（原价只在商品页出现），但这页的全部意义就是上市价对比，所以把上市价补在现价后面——灰字、划删除线、15px（两家共用那条规则，官网是 12px；放大是为了一眼看出原来多少钱，见 DESIGN-UNIQLO 第五节）。划线只在**真降了**的时候才画（`cut`）。

### 3.5 收藏 / 不再出现

> **2026-10-01 统一了两处**：报头的皮（字号/字距/小方块/发丝线/间距）和页面外壳
> （`.wrap` 原来 1280、`--pad` 24，现在跟优衣库对齐成 1560 / 40·24·16）。
> 原因是用户换页面时导航栏跟着变。代价是四列卡片会略宽一点（1280→1560）。
> 见 [DESIGN-UNIQLO.md](DESIGN-UNIQLO.md) 8.2b。

两个图标都落在**价格行的右端**——现价、黄角标、划线原价之后，靠 `margin-left: auto` 顶到卡片右边，不再单独占一行，两个都是 `size={16}`。

**尺寸这里踩过坑，值得记一笔**：lucide 全系画在 24 格上，但各个字形实际占多大差很多。爱心铺满 2→22，`EyeClosed` 也铺满 2→22，所以两者同尺寸（都量到 `14.6px` 的墨迹跨度）；而曾被换掉的那颗 `X` 只从 6 画到 18，同尺寸下只有爱心的六成宽，得单独放大到 24 才追得平——**换图标时不能默认同 size 就一样大，得看字形的墨迹跨度**。`EyeClosed` 的描边保持 lucide 默认的 2，它内部是弧形，在 16px 下加粗会糊。

「不再出现」这个图标试过几轮：

- 垃圾桶填成实心就是一只黑桶，跟一排彩色数字排在一起又重又钝；
- 叉号轻，但两条硬直线跟圆润的爱心并排像两个体系的东西；
- 划掉的眼睛（`EyeOff`）通用，但那条斜杠跟爱心一样抢眼；
- 最后落在 `EyeClosed`——三条弧线是全组里最安静的图形（**实测墨迹量只有实心爱心的 0.27，`EyeOff` 是 0.55**），而拿掉本来就是次要动作。

爱心一律实心，收没收改由**颜色**说：静着是官网未激活控件的灰（`#B3BAC3`），收了转品牌蓝（`#3643BA`）。闭眼是**永久**的：`hidden` 只增不减，没有放回（2026-09-30 把工具栏那颗「已隐藏 `N` 件 · 放回」和 `restoreHidden` 一起删了）。这一站一个款基本就一件，所以「按款删」和「按件删」在这里是同一件事（优衣库那边不同：一个款多个颜色、名字一样，见 [DESIGN-UNIQLO.md](DESIGN-UNIQLO.md) 第七节）。代价是误点没法撤，只能清浏览器存储；要跨设备就把它加进库里的谢绝名单（`deals decathlon block <编号>`）。

两本账存在 `localStorage` 的 `deca.picks` / `deca.dropped` / `deca.hidden` 三个键（前缀来自 `meta.storagePrefix`）。「待拔草」是三份来源合出来的：终端 `deals decathlon track` 进来的 ∪ 报告里收藏的 − 报告里取消收藏的。那个减号不是多余的一层，因为命令行**只有 `track`、还没有 `untrack`**：对一件已经 `track` 的商品，取消收藏只能在报告这边记一笔把它压住，否则刷新一下它又从数据库里冒回来。键名不许改（契约第五节）。

### 4.1 配色

配色和排版不是「看着像」，是把 `decathlon.com.cn` 的**计算样式**读出来照抄的：

| 项 | 官网实测值 | 用在哪 |
| --- | --- | --- |
| 正文 | `16px` / 行高 `24px` | `body` |

| 次要文字 | `#616161` | 品牌前缀、划线原价 |
| 未激活控件 | `#B3BAC3` | 筛选里没选中的、没收的爱心 |
| 折扣黄 | `#FFCD4E`，字 `#101010` | `-90%` 角标（官网 40 处） |
| 清仓红 | `#E20C18` | 「尾货」角标（官网 38 处） |
| 品牌蓝 | `#3643BA` | 链接、hover、选中态、焦点框、收了的那颗爱心 |
| 发丝线 | `#EFF1F3` / `#D9DDE1`，一律 1px 直角 | 表格分隔、标尺轨道 |
| 圆角 | `0`，全站直角 | 同 |
| 卡片 | padding `10px`、**网格列间距 0** | `.card` / `.grid` |

### 4.2 三条量出来的排版规矩

- 网格**列间距 0**（官网是 `grid-cols-4`，`column-gap: normal`），卡片贴着排，留白全靠卡片自己的 padding。
- 价格分三段：`￥` `14px`、整数/小数 `16px`，整段 `600` 字重。划线原价那行三格都是 `12px`。
- 商品名 `16px` / 行高 `24px`、容器高 `48px` —— 正好两行，多的截掉。

（`￥` 是全角符号，官网 DOM 里就是 `￥29.90`；零值写 `￥0`。优衣库那份是 `¥`、零值写 `¥ 0`——同一段拆价代码靠 `meta.currency` 分岔。）

### 4.3 一个「读计算样式查不出来」的坑（排序下拉框，已撤）

> 这一节记的坑当时出在排序那个 `<select>` 上；那个控件 2026-09-30 撤掉了，但这个坑对将来任何一个 `<select>` 都成立，所以留着。

那个下拉框一直是圆角的。CSS 里明明写了 `border-radius: 0`，`getComputedStyle` 读回来也确实是 `0px`，但屏幕上就是圆的——因为 `<select>` 是浏览器**特判**的控件，macOS 会在平台层画一个圆角外框盖在作者样式之上，**平台绘制的结果不反映在计算样式里**。所以只写 `border-radius: 0` 没用，必须 `appearance: none` 把平台外观整个关掉；代价是原生下拉箭头一起没了，箭头得自己画（当时用的是内联 SVG 直角折线）。

这件事说明**「照计算样式抄」这套方法有系统性盲区**：它能覆盖颜色、字号、间距、圆角这类由 CSS 决定的东西，但覆盖不了由平台绘制的外观。那一轮的自动校验全部通过，问题还是靠眼睛发现的。

### 4.4 大图视图：照官网分类页实测的网格

| 项 | 官网实测值 | 用在这页 |
| --- | --- | --- |
| 网格 | `lg:grid-cols-4 mn:grid-cols-3 mix:grid-cols-2` | 4 / 3 / 2 / 1 档，1440 宽落 4 列 |
| 卡片 | 无圆角、无边框、无投影 | 同 |
| 商品图 | 正方形，`object-fit: contain` | `aspect-ratio: 1/1` |
| 商品名 | `16px` / `400`，最多两行 | `.card__name`（`-webkit-line-clamp: 2`） |
| 促销价 | `16px` / `600` | `.card__now` |
| 折扣角标 | `#FFCD4E` / `10px` / 高 `16px` | `.offbadge` |
| 角标（尾货） | `#E20C18` / 白字 `12px` / 高 `24px` / 贴图片左上角 | `.tagbox` |

图片比例是 **1:1**（迪卡侬官图就是正方形，`object-fit: contain`）。**卡片图不写 `width`/`height` 属性**：属性会变成 used height、把 CSS 的 `aspect-ratio` 顶掉。卡片图不写尺寸属性，形状全由 CSS 的 `aspect-ratio` 定。

### 4.5 响应式：九档实测

列数档位照官网的 Tailwind 断点：**>1180 四列，≤1180 三列，≤900 两列，≤620 单列**。

工具条在 ≤760 只留页签一行，并且**钉住**（`position: sticky` 来自共用骨架）：搜索撤掉（`display: none`），剩下一行 58px。合并时这里曾经按「拿高度说话」把迪卡侬设成 `static` 让它滚走——依据是那一档它有两行 104px，常驻太占地；后来（用户要求）改成跟优衣库一致的「只留一行 + 钉住」，两行的前提就没了。1302 件商品，滚到中段想换个页签「只看尾货」，不该一路滚回顶部。

>760 宽时工具栏里有页签 + 搜索，≤760 只剩页签一行。九档实测：

| 宽度 | 1440 | 1280 | 1100 | 900 | 761 | 760 | 620 | 480 | 380 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 工具栏高度 | 58 | 58 | 58 | 58 | 58 | 58 | 58 | 58 | 58 |
| 工具栏里可见的控件组 | 3 | 3 | 3 | 3 | 3 | 1 | 1 | 1 | 1 |
| 网格列数 | 4 | 4 | 3 | 2 | 2 | 2 | 1 | 1 | 1 |
| `position` | sticky | sticky | sticky | sticky | sticky | sticky | sticky | sticky | sticky |

这一站九档全是 `58px`：撤掉排序控件和那格计数之后，工具条一次都不折行（对比优衣库 380 宽时页签会换成两行）。761 → 760 这一步换的不是 `position`（全程 sticky），而是**工具栏的内容**：搜索与计数撤掉，只剩页签。

**0.5px 的坑**：工具栏真实高度是小数，和下边内容之间会留下 0.5px 没有白底盖住——滚动时从这条缝里会透出行内容，2x 屏上正好是一个物理像素宽的闪烁细线。修法是让工具栏自己的白底往下多铺 1px（`box-shadow: 0 1px 0 #fff`）：它不参与布局，所以工具栏高度不受影响。

**`position: sticky` 只能在自己的父元素盒子里活动**：工具条得是「`.toolbar`（整页宽、只负责粘）＞ `.wrap`（对齐）＞ `.toolbar__row`（flex 排布）」三层，最外层父盒子是整页高的 `#root`，才真的粘得住；否则它看着是粘住了，其实早在父盒子底部就停住了。

复测结果：横向溢出全部为 `0`；网格列数逐档 4 / 4 / 3 / 2 / 2 / 2 / 1 / 1 / 1，跟断点规则逐档对得上；窄屏（≤760）滚到 1800 处，`.toolbar` 停在 `top: 0`、高 58px，页签一直看得到。

## 五、图片：两个图床，两套缩放写法

抓来的图片地址来自两个不同的图床，缩放方式完全不同，**这是踩过的坑**：

| 图床 | 缩放方式 | 实测 |
| --- | --- | --- |
| `pixl.decathlon.com.cn` | 尺寸插在**路径**里：`/800x800/content.jpg` | 25KB（原图 215KB）；`?width=800` 完全无效，只会拿到原图 |
| `easymerch-oss.object.decathlon.com.cn` | 阿里云 OSS，路径**不能**插尺寸，要走 `?x-oss-process=image/resize,w_800/quality,q_80` | 122KB（原图 502KB） |

OSS 那档实测 `resize,w_800` 单独用只从 502KB 降到 419KB（源图本身不大），加上 `quality,q_80` 才降到 122KB——所以 OSS 那条必须两个参数一起给。

pixl 的 400 / 800 / 1000 / 1600 都正常，**没有优衣库那种中间档全 404 的坑**，所以这一站选 `800`（`imageSize: 800`）。

**候选图全挂的商品不上榜**（2026-09-30 起）。这一站有 32 件是这样：官网自己就没图（冷门备件最常见），或者图早从 CDN 上撤了。以前它们会在榜上留一个灰框，现在生成报告时直接剔除——看不到东西就没法买。剔除发生在 `core/report.mjs` 的 `buildPayload`：只在 `images` 传进来那一趟过滤，因为传 `null` 那一趟是给 `ensureImages` 用的候选清单，过滤了就没图可下。商品仍留在库里，终端 `list` 里仍看得到，图哪天有了就自动回来。优衣库那边选的是 `561`：两家各写各的档位规则，`sizeVariant(url, size)` 由站点适配器提供，共享核心只负责「把 URL 交出去、把字节收回来」。**认不出的形状原样返回**——宁可用原图，也不要拼出一个 404 的地址。

### 5.1 主图会 410，副图还在 → 候选链

一个 model 通常带 3 张图（主图 + 两张副图）。实测有 **130 件的首图**在 CDN 上已经永久消失（HTTP `410 Gone`，原图和缩放档都是 410），但**同一个 model 的副图仍然可用**。

所以整串图都留着，下载时按顺序试，第一张下来了就停。把「只读第一张」改成候选链之后，失败数从 **275 件（21%）降到 29 件**，而且这 29 件是**所有候选图都 410**——报告里留灰占位框，终端跑 `report` 时也会列出来是哪些（这是数据，不是 bug）。

下载侧的取舍：4xx 是「这张图不存在」，重试没意义，直接换候选；5xx 或超时是网络抖动，同一张图再试一次。并发 8，每 20 张回一次进度——两家都是上千件商品，太密的回调只是白刷屏。

图片仍然抓到本地（`reports/decathlon/img/`）：报告要能离线看，且尾货卖完就下架，下架后外链就是破图。文件名带档位与格式（`X8839690@800.webp`）：落盘前统一过一次 WebP（同优衣库，见 core/images.mjs），换档位/换格式时不会把旧的当缓存命中。

**优衣库那半只需要一张图**，候选链长度是 1；共享核心统一按候选链处理，逻辑完全一样。

## 六、字体：不内嵌，走系统字体栈

官网的 `@font-face` 声明的是 `font-family: "Roboto"; src: .../DECATHLON-Medium.ttf` —— 这里的 `Roboto` **是迪卡侬的品牌字体**（不是 Google 那个开源的 Roboto），不能内嵌。中文本来就落到系统字体上。

所以这一版**没有内嵌任何字体**：

```
Roboto, Decathlon, 'Helvetica Neue', Helvetica, Arial, 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', sans-serif
```

对应到契约里，就是适配器的 `fonts: null`。共享核心里的字体代码留着、由站点描述符驱动：`fonts: null` 就是不内嵌。这也意味着：

- 这一份报告没有「首次运行下载 16MB 字体」那一步，`deals decathlon report` 不需要 `data/fonts/`；
- `--no-font` 对它是空操作；
- 没有字体署名要写（署名不能省的那份是 Apache-2.0 的思源黑体，属于优衣库那半）。

这跟隔壁优衣库那份（内嵌了 Apache-2.0 的思源黑体子集、并把 Medium 挂到 700 槽位上）不一样，是顺着数据源来的：那边官方用的思源黑体可以直接拿来用，这边不能。

## 八、终端、部署与已知情况

### 8.1 终端那张表

迪卡侬那份的列（`tableColumns`，由站点声明、共享核心只负责画）：`编号 | 商品 | 上市价 | 现价 | 降幅 | 省 | 品牌 | 标签`。

第 7 列是**品牌**，没有销量列——这是和优衣库那份最直观的差别（优衣库没有品牌列；它原先那列「月销」因为接口字段数值自相矛盾，已于 2026-09-30 撤掉）。「省」按整数写（`toFixed(0)`）。标签列滤掉 `discount_zone`，其余按 `TAGS` 译名。

`list` 的排序口径：`--sort rate|saving|price|newest`（`price` 是这一站独有的排序键，看绝对低价）；`--tag endlife|new_arrival`；默认门槛降幅 ≥30%。`track <编号>` 的编号是商品页地址里的 `dsm_code`（也可以直接贴地址，`parseCode` 从里面抠 `\d{5,9}`）；手动盯的商品按第一个命中的标签解释性质——尾货＝清仓会继续降但容易断码，新品＝刚上架就在打折。

`stats` 比优衣库多一行站点私有统计（`statsExtra`）：**其中尾货清仓 N 件**。

`history <编号>` 原来是这一站独有的命令，现在两家都有；它**只读本地快照、不去接口核对**——能查历史的多半是已经下架、或者早就不在特惠区里的商品，正是接口查不到而本地还留着记录的那些。

### 8.2 部署

`vercelProject: 'decathlon-deals'`，所以 `deals decathlon deploy` 生成最新报告后执行 `vercel deploy reports/decathlon --project decathlon-deals --prod --yes`。部署的注意事项（快照、收藏不会跟过去、默认公开）见 [README.md](../README.md)。

### 8.3 已知情况

- 报告里放的是**降幅 ≥15%** 的商品（`buildPayload` 的 `minRate: 0.15`），不是全部；终端 `list` 默认门槛是 ≥30%。
- 29 件商品在报告里是灰占位框（所有候选图都 410），终端跑 `report` 时会列出编号。
- 「历史最低」数据层一直在记（`min_price_ever` / `min_price_at`），但报告**故意不展示**：只有一天快照时它必然等于现价，于是每一件都挂着「历史最低」的标——一个全都命中的标记等于没有标记。等快照攒到几周、这个判断真能区分开商品时再接回来。

### 8.4 刻意不做的事（汇总）

| 不做 | 为什么 |
| --- | --- |
| 不内嵌任何字体 | 官网那个 `Roboto` 是品牌字体，不能内嵌；中文本来就走系统字体 |
| 不把 `discount_rate` 当降幅 | 它是「折」，直接当降幅用会得到完全颠倒的排序；一律用两个价格现算 |
| 不用 `filter=discount_range` 筛全站 | 那条路实测后端会串页；一个分类翻 14 页稳定得多 |
| 不在页面上标「特惠专区」 | 1391 件里 1374 件都带着它，一个全都命中的标签等于没有标签 |
| 不摆页顶榜单 | 商品名下面是「品牌 + 编号」，榜单里再念一遍品牌很啰嗦（优衣库才有榜单） |
| 不在页面上写名词解释 | 上市价 / 折与降幅 / 尾货 / 新品 / 标尺怎么读都在 README，不占页面（`foot.terms` 是空数组） |
| 不显示「历史最低」 | 一天快照时它必然等于现价，全都命中等于没有标记；数据层照记 |
| 不显示总账数字 | 对「这一件要不要买」没有任何帮助 |
| 不写卡片图的 `width`/`height` 属性 | 属性变成 used height 会顶掉 `aspect-ratio` |
| 不引 CDN 图片 | 报告要能离线看，且尾货下架后外链就是破图/410 |
| 不硬画没降价商品的标尺 | 一根 `-0%` 的空条看着像在打折；改写「尚未降价，正在替你盯着」 |
| 不用「折」写价格行 | 和榜单、标尺的口径统一成降幅百分比 |

### 8.5 抓取节奏

`sync` 每页之间 `sleep(200ms)`，14 页实测约 25 秒。合并后建议每天 `sync` 一次攒历史（现在由 GitHub Actions 每天北京时间 09:00 自动跑一轮，见 [README.md](../README.md) 的「自动化」一节）。
